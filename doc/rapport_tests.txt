═══════════════════════════════════════════════════════
PROBLÈMES TECHNIQUES NOTABLES
═══════════════════════════════════════════════════════

A. Contrainte unique_together Employee ('organization', 'employee_id')
   → Tous les tests créant plusieurs Employee doivent fournir un
     employee_id unique ('KPI001', 'PLAN002', etc.) sinon IntegrityError.

B. cache_response incompatible avec @api_view (FBV)
   → Le décorateur core/cache.py utilise wrapper(self, request, ...) :
     conçu pour les méthodes de classe. Sur une FBV, self capture request
     et request est manquant → TypeError.

C. Router DRF avec préfixe vide
   → router.register('', ViewSet) génère des URLs d'actions comme
     ^/mark-all-read/ (slash initial), interceptées par le pattern detail
     avant d'atteindre l'action. Solution : préfixe non-vide ('items').

D. Celery en mode test
   → Les tâches .delay() ne s'exécutent pas en test Django standard.
     Solution : @patch('module.task', autospec=True) pour mocker l'appel.
